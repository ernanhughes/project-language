# Optional negotiated transfer v1 — separate prospective comparison

Status: offline scripted development extension, **not an approved live pilot**. SOURCE / PLAIN / LINKED / CONTEXT, their receipts and the TRANSFER-01B qualification lock remain unchanged. No NEGOTIATED condition is inserted into their existing schedule.

Three proposed, unadjudicated synthetic cases cover licensing resolved while separate publication approval remains absent; licensing still unresolved; and a staging-only clarification that does not relax production retention. Fixtures and expected outcomes live in `src/negotiated-v1/protocol.mjs`, identified by version/source hashes. They are not guaranteed absent from model training and have no independent human adjudication.

For each case, compare DIRECT_REVISED with NEGOTIATED. Both get the same original expression, the same reviewer opportunity, the same explicit clarification and the same accepted facts. Both use four request opportunities: initial interpreter, reviewer, revised interpreter, fresh recipient. Both permit the same correction. Direct transfer serializes accepted facts as an ordinary revised record; negotiated transfer carries the validated state, source references and revision metadata. Byte overhead, local latency and correction calls are reported rather than hidden. This isolates representation after equal clarification opportunities; it cannot establish the causal benefit of negotiation versus no review.

All interpreter/reviewer/recipient responses are hand-authored faux outputs returned through real Pi sessions. The operator decision is pre-committed and labelled SIMULATED_HUMAN in its input, acceptance receipt, envelope and viewer. No actual human acceptance or action permission is inferred. Resolving a condition never creates an action grant. No real provider or credentials are used; no provider runtime is copied from Python.

The fresh recipient gets only accepted transfer and a new decision question. It does not get original conversation, pending proposals, reviewer history, the host answer key or prior evaluator judgments. The interpreter/reviewer do not receive this novel question. Reviewer B is not the independent evaluator; C is a fresh recipient. Primary assessment stays NOT_ADJUDICATED. Authored exact-decision comparison is a scripted diagnostic, not demonstrated comprehension; phrase repetition alone would not pass the proposed decision response contract.

Local ceiling: 24 faux requests for three cases × two arms × four stages, 2,048 output tokens reserved per call, 8,192 output bytes, 4,096 transferred bytes and one-second offline deadlines, zero retries/fallback. Actual model token consumption is UNKNOWN and actual model spend is US$0. Negative runs deliberately worsen negotiated answers, or refuse acceptance and stop before the recipient. They remain separate historical controls, not repairs to the successful trace.

Future live design requires separately approved tasks, independent source-bound judgment, exact three-role models/routes, response/token/billing qualification, equal information and correction opportunities, and a new source/settings/call/spending lock. No fixed live model assignments or spending authorization are created here. This extension is outside the unapproved 48-call main TRANSFER pilot. Taint is not computed or transmitted; no hidden personal memory is used.

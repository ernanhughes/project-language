# Model runtime — LC-01R OpenCode

OpenCode Go is the active provider; it is remote subscription inference, not local/free inference. The normal launcher selects DeepSeek V4.1 Flash (interpreter and mediator), GPT-6 Luna (challenger), Qwen3.8 Flash (recipient), and optional Haiku 5.5 (advisory role, execution still deferred). Fixtures remain available via `--fixtures` or individual role selectors. The isolated `ollama-legacy.mjs` and original truncation evidence are preserved; the active launcher never discovers or calls Ollama.

Studio imports this repository's Pi 1.0.4. The desktop Pi launcher is independently installed at 1.4.0 and does include Haiku. `config/models.json` uses Pi's supported application-scoped registration: three existing 1.0.4 definitions plus Haiku metadata from installed 1.4.0. No dependency/global configuration changed. The application overlays the currently documented Go endpoint generation: OpenAI families use `/inference/go/openai/v1`; Messages uses `/inference/go/anthropic`, with SDK `/v1/messages?beta=true`. Metadata, route and price origin are explicit. Go never falls back to Console.

`ModelRuntime` uses in-memory credential and model stores, network refresh disabled. No saved authentication file or .env is accessed. The only live credential source is process `OPENCODE_API_KEY`, passed explicitly at dispatch. The provider fetch boundary captures the actual serialized body, never authentication headers. Strings/secret fields are redacted before journal/export, including echoed keys and provider errors. Unsafe provider error details are hashed, not displayed.

Remote dispatch requires `--enable-remote`, the process key, a matching finite plan, and explicit UI confirmation of remote use and Go workload appropriateness. Approval is never restored on replay. Changed role assignments or settings revoke it. Default: 6 total attempts, US$1 estimated ceiling, 90 seconds, interpreter/mediator output 8192, other roles 4096. SDK/automatic retries are zero. Repeating a failed action is a new recorded development attempt, counted/reserved before dispatch; failed attempts are never overwritten. Session counts/reservations survive replay. No state is manufactured on malformed, incomplete, truncated or failed responses.

Every request records exact system/user text, JSON schema prompt, isolated session ID, route/model/API, request settings and prompt hash. Every response records redacted raw output, usage if reported, latency, actual attempts and status. Model-supplied JSON is parsed and strictly validated without stripping fences or repairing content. The protocol's original source/acceptance checks remain intact. Advisory evaluation is not source truth or human acceptance.

Offline qualification uses actual installed Pi serializers with injected SSE fixtures for Completions, Responses and Messages. Its source/config-bound receipt is `config/offline-qualification.json`. OFFLINE_ADAPTER_VERIFIED_LIVE_NOT_PROBED means serializer/fixture tests passed, never remote availability, authentication or semantic qualification. Missing advisory registration shows ADVISORY_EVALUATOR_UNAVAILABLE without blocking core roles.

Official reference checked 2026-10-23: https://dev.opencode.ai/v2/docs/console/go . It describes typical coding-agent traffic and monitored service limits. This research workload's appropriateness requires operator confirmation; the app identifies honestly as `language-studio/0.1r` and sends stable per-call conversation headers. No live requests are authorized by the implementation task.

## LC-01S prospective qualification

`config/lc-01s-offline-qualification.json` is the new source/config-bound receipt; the LC-01R receipt is preserved. The selected receipt digest participates in the displayed plan identity. `--task` selects a strict, source-hashed prospective task, and `--expected-plan-hash` rejects drift before startup. Stream-byte accounting now records Response.body bytes/chunks before SSE parsing, with a 1 MiB ceiling. The former 256 KiB ceiling is preserved in `config/history/lc-01r-studio.json`; every other request/token/time/reservation/retry setting is unchanged.

Offline default runtime initialization uses an empty credential environment; it does not inspect process secrets. Only a later explicitly enabled remote launcher selects process OPENCODE_API_KEY. Accepted version content is rehashed before transfer. Test acceptance cannot authorize a real hosted recipient. The single-operator UI still requires the product owner to personally decide; local actor labels are not signed proof of physical presence. See LC-01S-REPORT.md for the unresolved service-use applicability and no-live-authorization status.

# LC-02 — Semantic enhancement comparison

Status: OFFLINE_IMPLEMENTED; EXPOSED_DEVELOPMENT; NO_NEW_REMOTE_INFERENCE.

The question is whether intelligence in the communication channel improves the meaning reconstructed by a recipient. Cost is an operational constraint, not an outcome or semantic score.

## Two paths

| Ordinary | Language-mediated |
|---|---|
| Full original source prose, sender intent, purpose and audience | The same full source, intent, purpose and audience, plus an accepted source-linked interpretation |
| Every human clarification, verbatim | The same human clarifications, verbatim |
| Fresh recipient with the withheld application question | Separate fresh recipient, same configured model, same question and request settings |

The interpreter never receives the application question. Both packets are sealed before question exposure. Requests have unique session IDs and no prior conversation. The recipient receives no candidate reference or fixture outcome. Order is specified per case and alternates across the suite; three cases are insufficient to estimate order effects. Exact system instructions, output schemas, input messages, source, response and failures are captured in the chained event journal. This tests mediated communication as a package: extra interpretation and human review are confounds for any claim about representation alone. No full-transcript preservation claim is made.

An interpreter proposes a version using the existing Proposal contract. Hosted execution stops for a human to review that exact version. Acceptance permits communication only. Rejection stops the comparison. Optional clarification invokes the existing mediator, creates a new version and requires review again; the exact clarification is then included in both arms. Previously accepted authority is not expanded. Fixture acceptance is explicitly TEST_OPERATOR and cannot be passed off as actual human judgment.

## Three distinct evaluations

1. Mechanical: strict schema, original-source quotation/span binding, source equality, version/acceptance integrity. A binding quotation may still fail to support an answer.
2. Candidate reference: decision agreement and potential false permissions against UNADJUDICATED_REFERENCE. Agreement is not proof of comprehension.
3. Semantic review: correct interpretation; important information retained; important information lost; unsupported inferences; ambiguity discovered; handling unknowns; decision quality; clarification/negotiated correction. Initially every criterion is NOT_ADJUDICATED. Human-entered assessments append a separate record and never overwrite raw answers or mechanical checks.

Assessment values are SUPPORTED, UNSUPPORTED, UNCLEAR and NOT_ADJUDICATED. They describe whether evidence supports the named criterion, not a numerical quality scale. SUPPORTED important_information_lost means loss occurred; it is adverse. Reviewers should cite relevant source statements and explain omissions, invented permissions and uncertainty. No aggregate enhancement score, p-value or independent-human-agreement claim is calculated. An entered reviewer identifier is an assertion, not identity verification.

## First offline suite

All three cases are exposed, synthetic and authored by the implementation agent. The responses are deliberately scripted to exercise displays and failure distinctions. They are not model measurements.

| Illustration | Ordinary | Language | Meaning |
|---|---|---|---|
| Readiness and authority | YES | NO | Constructed potential help: avoids treating readiness/rollback as production approval |
| Straightforward boundary | NO | NO | Constructed tie: ordinary prose suffices |
| Unresolved review | UNKNOWN | YES | Constructed potential harm: mediation invents production permission from ambiguous review |

The harmful proposal can pass mechanical schema checks. That is intentional: mechanics must not certify semantic truth. No effect size or superiority claim follows from these fixtures.

Before their execution, pin exact source/intent/task, provisional references with rationale and uncertainties, both arm definitions, model identities, order and semantic rubric prospectively. Keep evaluation questions and candidate decisions out of sender/interpreter inputs. Do not relabel development cases as held-out. A human or separately commissioned AI reviewer may advise; identify its provenance and do not call AI-only review independent human adjudication.

Review actual paired answers with concealed arm labels where feasible, preserve ties and disagreement, distinguish missing/invalid responses from semantic mistakes, and retain all failures. Whether the ordinary arm needs an equivalent interactive clarification policy must be specified before any stronger negotiated-communication comparison. This implementation shares all human clarifications, but only the Language path produces a derived interpretation; it cannot isolate a negotiation advantage.

## Infrastructure and execution

Simple Mode defaults to Start Comparison → See Results using fixtures. Real execution remains disabled by the ordinary launcher. Advanced / Infrastructure contains models, credentials-availability status, finite plan, request limits, provider approvals, usage, failures and full trace exports. Changing models/settings invalidates approval; saving identical settings does not. Approval is deliberately not restored after a restart. A different task scope also revokes approval, and legacy S-17 inference cannot run under comparison approval.

Future remote development execution uses one selected case, three requests (interpreter plus two recipients), or one additional request per explicitly requested clarification, always within the existing total finite ceiling. No retries or fallback are introduced. Exact semantic acceptance remains a separate action. This task authorizes no new hosted calls. Old qualification receipts/plans are preserved; changed source bytes are not a reproduction of LC-01. Prospective live qualification and authorization remain separate work.

## Reuse and boundaries

The controller reuses Studio.version, decide and packet, Proposal/Answer schemas, source anchors, Runtime provider gates and Log's chained evidence. Comparison state uses its own journal event and does not replace the S-17 exchange. This is an extension of the existing application, not another runtime. The book's capability-provider registry was consulted: evidence/provenance and authority contracts are already consumed by the parent core and Studio; the missing paired comparison orchestration and rubric belong here. No provider/plugin is installed or reimplemented.

The same source → proposed transformation → acceptance → delivered message → reconstruction → assessment contracts can later support human input, AI participants and human recipients. The current recipient adapter is AI/fixture only. Human-recipient tasks and iterative multi-participant protocols are design extensions, not implemented or validated capabilities.

## Open questions

Does mediation retain conditions better, or merely repeat them? Does a recipient apply a revision on a new decision? Can ambiguity be discovered without inventing a resolution? When does extra structure distract or induce unjustified trust? Does any improvement survive a baseline allowed the same clarification opportunity? How much of an effect belongs to review or extra computation? These require independently designed cases and real paired observations.
